# 질문 범위·사용량 검토 빌드

이번 묶음은 main 대비 검토에서 확인한 질문 컨텍스트 결함과 비용을 확인할 기반을 수정한다. 화면 취향·분야별 번역 의미 판단은 사용자에게 맡긴다.

## 변경

- 페이지 첨부를 현재 캐시의 해당 페이지 원문으로 확장. 본문이 없으면 보내기 전에 설명하며 초안 보존. 긴 페이지는 명시적인 부분 발췌로 제공한다.
- 현재 논문 선택 해제 복원. 최대 8편 선택 안내와 전송 경계 검사. 직접 첨부가 다른 논문을 추가하는 경우도 검사한다.
- 질문+직접 근거+초록+자동 발췌 합계를 46,000자 이내로 구성. 자동 발췌와 초록을 먼저 줄이고, 직접 입력만으로 초과하면 초안을 보존하며 나누어 질문하도록 안내한다. 이 값은 토큰 추정치가 아니라 직렬화된 전송 문자열 제한이다.
- 새 대화에 보관함 경로를 기록하고 다른 보관함에서 재개하지 못하게 한다. 준비 도중 보관함 변경은 실제 CLI 호출 전에 검사한다. 자동 노트 갱신에서도 다른 보관함/소유권 불명 대화를 제외한다. 대화 저장은 원자적 쓰기를 순서대로 실행한다.
- 보관함 변경 시 질문에 담긴 논문 선택과 근거 칩을 초기화한다. 질문 텍스트는 유지한다.
- 설정 → AI 사용 기록: 최근 10개 표시, 로컬 최대 500개 기록. 질문·논문 본문은 기록하지 않는다. 입력·캐시·출력은 CLI 제공값만 사용하고 미제공은 미제공으로 표시한다.
- Codex 채팅 수치는 마지막 모델 요청임을 표시한다. 여러 도구 호출을 포함한 턴 전체 청구량으로 오인하지 않게 한다. Claude/일회성 실행은 결과 usage를 정규화한다. 캐시 입력은 전체 입력에 포함된다.
- Codex 새 대화와 재개 시 작업 디렉터리를 동일하게 유지한다.
- CI의 임시 경로를 생성 직후 realpath로 정규화하여 Windows 단축 경로와 macOS /private 별칭에 대응한다.

## 개발자 검증

- 빌드 및 전체 core 검사 통과.
- 신규 검사: 실제 페이지 본문 전달, 본문 없는 페이지, 직접/자동 논문 8편 한도, 전체 문자열 예산, 중복 근거, 일반 질문의 빈 논문 범위.
- 신규 검사: 보관함 변경·다른 보관함 대화 재개·이전 버전 소유권 불명 처리·동일 논문 ID의 두 보관함 자동 정리 분리.
- 신규 검사: Codex/Claude 토큰 필드, 미제공 값, 음수 값, 동시 기록, 500개 보존, 중복 완료 기록.
- Product UI 통과. 실제 PDF를 가져온 앱에서 현재 논문 선택 해제→다시 선택→현재 페이지 첨부→보내기를 수행하고, IPC 직전 요청에 실제 본문이 포함되는지 검사. 유료 CLI 호출은 테스트 호스트에서 차단한다.

- 패키지와 CI 최종 결과는 `release/context-review/BUILD-INFO.json`에 기록한다.

## 사용자가 확인할 것 — 약 10분

Windows 검토 빌드: `release/context-review/Prism-0.1.0-Windows-x64.exe`.
익숙한 논문 1편으로 시작한다. 기존 보관함을 사용해도 되지만 중요한 연구 자료는 평소처럼 백업한다. 이전 버전 대화는 읽을 수 있으며 이번 검토는 **새 대화**에서 시작한다. 모델은 기본 Luna/Haiku로 충분하다.

1. **페이지 설명:** 원문 2쪽 이후로 이동 → 더보기 → 현재 페이지 근거로 담기 → “이 페이지에서 설명하는 핵심을 짧게 알려줘”. 답변이 그 페이지를 설명하는지, 출처를 눌렀을 때 위치가 이해되는지만 확인한다.
2. **질문 범위:** 채팅 위 논문 선택에서 현재 논문 선택 해제 → 새 대화에서 일반 개념 질문 1개. 선택 상태가 명확한지 확인한다. 이어 논문 2편을 선택해 차이를 짧게 질문해도 된다. 기존 대화의 기억 자체를 지우는 기능은 아니므로 일반 질문은 새 대화로 시험한다.
3. **기록 확인:** 설정 → AI 사용 기록 → 보기. 방금 질문의 모델·시간·토큰 항목이 읽기 쉬운지 확인한다. 값이 미제공이면 그 상태 그대로 알려주면 된다. 숫자가 적절한지는 개발자가 판단한다.

답변은 아래처럼 짧게 주면 된다. 번역·노트 전체·디자인 전체를 이번에 다시 검수할 필요는 없다.

```text
1 페이지 질문: 잘 됨 / 이상함 — 논문·페이지와 이상한 부분
2 질문 범위: 잘 됨 / 헷갈림 — 어디서 헷갈렸는지
3 사용 기록: 보임 / 안 보임 / 읽기 어려움
꼭 바꾸고 싶은 점: (없으면 생략)
```

## 남은 한계

- 실제 모델을 새로 호출하지 않았으므로 토큰 절감률이나 번역 의미 품질 향상을 주장하지 않는다.
- 보관함 정보가 없는 이전 대화는 다른 보관함에 연결하지 않고 새 대화를 안내한다. 이전 기록은 삭제하지 않는다. 경로 기반 소유권이므로 보관함을 다른 경로로 옮겼을 때의 명시적 대화 이관은 후속 작업이다.
- CLI 공통 설정·도구의 기본 입력량을 완전히 격리하지 않았다. 번역의 짧은 요청별 프로세스 비용, 대화 압축과 출처 재주입, 이미지 해상도 예산은 새 계측값을 기준으로 다음 묶음에서 다룬다.
- 사용량 기록은 과금 명세서가 아니다. CLI 시작 이전 오류나 연결이 갑자기 종료된 경우 기록이 남지 않을 수 있다. Codex 채팅은 마지막 요청 수치이며 턴 전체 합계가 아니다.
- 수동 선택 해제는 이후 요청의 새 발췌를 제외한다. 이미 같은 CLI 대화에 전달된 과거 내용을 제거하지는 않는다.
