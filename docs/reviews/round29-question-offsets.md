# 여러 문단 질문에서 근거 삽입 위치

2026-09-10. 이전 루프는 실제 DOI 복원, 근거 표시, 붙여넣기 스크롤을 변경하고 검증한 진행이었다. 이번에는 57e58e5의 깨끗한 작업 트리에서 질문의 문단과 근거 위치를 점검했다.

## 관찰과 한계

기존 코드는 입력창 내용을 읽을 때 DIV 문단을 줄바꿈으로 계산했지만 커서 앞부분은 textContent로 계산했다. 또한 본문의 연속 개행을 줄인 뒤에도 근거 위치는 줄이기 전의 인덱스를 사용했다. DOM 형태에 따라 내용과 위치 계산이 달라질 수 있는 코드상의 불일치다.

독립 비평 담당이 기존 빌드에서 세 문단 붙여넣기와 실제 Shift+Enter 두 번으로 문단을 나누는 경로를 각각 확인했다. 둘째 문단의 `여기 ` 뒤에 PDF 문장을 담았을 때 두 경로 모두 의도한 위치에 삽입됐다. 이 화면 검토에서 위치 오류가 재현됐다고 주장하지 않는다. 문단 텍스트는 도구의 type_text 입력이며 순수 키별 타이핑 검증은 아니다.

## 변경

본문 전체와 커서 앞 DOM 조각을 같은 함수로 읽는다. 근거 칩의 화면 라벨은 질문 텍스트로 넣지 않고, 사용자 빈 줄을 임의로 축약하지 않는다. 문단과 근거 위치가 동일한 기준을 사용하도록 중복 구현을 제거했다.

회귀 검사는 문단 DOM·BR·P 요소, 근거 표시 제외, 연속 빈 줄 보존과 삽입 위치를 포함한다. 실제 Electron Product UI에서는 채팅을 열고 `첫 문단.\n\n\n둘째 문단: 여기 뒤에 근거를 넣습니다.\n셋째 문단.`을 입력한 뒤 둘째 문단 중간에 피겨를 담아 앞부분이 빈 줄까지 정확히 일치하는지 확인한다. 기존 질문 끝에 긴 텍스트를 붙여넣을 때 마지막 빈 줄이 보이는 검사와 첨부 전달 검사도 유지한다.

최종 빌드, 전체 core 검사, Product UI 검사가 통과했다. 자동 검사를 작성하는 과정에서 숨겨진 채팅 입력창에 입력을 시도한 테스트 준비 오류를 수정했으며, 이를 제품 결함으로 분류하지 않는다. 실제 AI 요청은 사용하지 않았다.
