# 통합 검토: 읽기 안내·개인 연구 메모·제품화

이 문서 하나를 기준으로 피드백하면 된다. 기존 `product-completion-2026-09-10.md`의 검토 항목과 이번 요청을 합쳤다. 앞서 사용자가 확인한 **논문 선택 모두 해제, AI 사용 기록 표시**는 반복 확인할 필요 없다.

## 검토 빌드

- Windows: `release/reading-memory/Prism-0.1.0-Windows-x64.exe`
- 같은 폴더의 `BUILD-INFO.json`에 소스 커밋과 실행 파일 SHA-256을 기록한다.
- 기존 앱을 종료한 뒤 이 실행 파일을 사용한다. 기존 보관함과 설정을 사용한다.
- 처음 읽기·자동 메모의 기본 모델은 Codex / gpt-5.6-luna. Claude를 쓰려면 설정에서 해당 작업의 CLI와 모델을 바꾼다.

## 이번에 추가한 동작

| 항목 | 동작 |
|---|---|
| 처음 읽기 | 원문 추출 후 모델이 요약과 발견·방법·한계의 핵심 위치를 고른다. 짧은 출처 번호를 실제 PDF 앵커로 변환·검증하고, 하이라이트와 논문 노트에 함께 저장한다. |
| 입력·재사용 | 논문 전반에서 최대 100개 원문 항목, 직렬화된 발췌 45,000자 이내로 제한한다. 현재는 25자 초과~1,600자 이하의 본문·제목·캡션을 후보로 쓴다. 긴 논문은 부분 읽기이며, 그림 이미지·표·수식 자체를 해석하는 작업은 아니다. 원문이 같으면 다시 열거나 모델만 바꿔도 재호출하지 않는다. 명시적 ‘다시 만들기’는 재호출한다. |
| 표시 전환 | 리더의 ‘AI 하이라이트’ 체크를 끄면 색상 표시만 사라진다. 노트·캐시는 보존되고 재실행에도 표시 선택이 유지된다. |
| 노트 동선 | 리더 ‘핵심 읽기 안내 → 읽기 노트 열기’. 노트 앞부분에 ‘핵심 읽기’, 개인 메모가 생기면 ‘나에게 남길 것’을 둔다. 기존 기계적 참고 목록은 기본 접힘으로 남기며 직접 펼칠 수 있다. |
| 자동 메모 | 앱 실행 중 대화가 끝나고 저장이 잠잠해진 뒤 처리한다. 먼저 로컬 규칙으로 후보를 골라, 모델이 연구 목적·적용 계획·남은 의문·판단 변화를 최대 6개 항목으로 선별한다. 일반 요약·감사 인사는 모델을 부르지 않는다. |
| 이해 판단 | AI가 설명했다는 사실만으로 이해했다고 저장하지 않는다. 사용자의 명시적 이해·해결 발언이 있어야 의문을 제거한다. 기존 질문 빈도 기반 의문 목록이 개인 메모와 경쟁하지 않도록 정리한다. |
| 연속 대화·실패 | 빠르게 이어진 여러 완료 답변도 순서대로 처리한다. 실패·중단된 답변, 다른 보관함 대화는 대상에서 제외한다. 같은 완료 답변을 반복 처리하지 않는다. 실패하면 기존 노트를 유지하고 오류를 표시한다. |
| 직접 작성 보호 | 직접 고친 AI 문단은 통째로 보존한다. 새 문장·바깥 영역·삭제 의도도 보존한다. 반복 공백·줄 끝 공백 등 공백만의 변경은 의미 있는 수정으로 취급하지 않는다. AI 실행 도중 저장한 수정도 최신 파일을 다시 읽어 보호한다. |
| 기존 자동 구간 | 앱에서 의미 있게 수정한 구간은 보호 표시를 남긴다. 새로 생성한 기존 자동 구간에는 내용 기준값을 기록해 외부 편집도 감지한다. 기준값 도입 전 외부에서 이미 수정된 구간의 작성 주체를 소급 판별하지는 못한다. |
| 설정 | 왼쪽 항목 탭: CLI 연결 / 처음 읽기 / 번역 / 대화 메모리 / 지식 정리 / 구조 분석 / 파일 보관 / 화면 / AI 사용 기록 / 키보드. 처음 읽기·번역·메모리·지식 정리·구조 분석 모델을 각각 선택한다. 채팅과 해당 대화의 문맥 정리는 대화 모델을 사용한다. |

## 실제 모델 검사

설치된 Codex CLI, gpt-5.6-luna, 전용 작업 지침, low effort. 로컬에 있던 *Attention Is All You Need* 원문과 격리된 검사용 노트를 사용했다. 개인 보관함은 수정하지 않았다.

| 작업 | 입력 문자 | 실제 입력 토큰 | 캐시 입력 | 출력 토큰 | 시간 |
|---|---:|---:|---:|---:|---:|
| 핵심 읽기 | 12,399 | 10,829 | 5,888 | 609 | 15.494초 |
| 연구 계획·남은 의문 | 3,311 | 9,105 | 0 | 127 | 7.453초 |
| 명시적 이해 이후 갱신 | 3,989 | 9,345 | 2,816 | 97 | 6.352초 |

- 하이라이트 7/7의 실제 앵커와 페이지 연결을 검증했다. 위 세 호출 모두 도구 호출 0회.
- “센서 시계열 예측에 적용”과 “디코더 마스킹이 아직 헷갈림”을 따로 저장했다. 다음 발언에서 이해를 확인하자 의문만 제거하고 적용 계획을 유지했다.
- 같은 원문 재열기와 일반 요약 질문은 모델을 호출하지 않았다. 직접 쓴 문장도 보존됐다.
- 앞선 1회 검사에서는 모델이 긴 원문 ID 한 개를 잘못 복사하여 검증 단계에서 저장을 거부했다. 짧은 번호 매핑으로 수정한 후 위 결과를 얻었다. 잘못된 원문 연결을 유추해서 허용하지 않는다.
- 이 표본은 전체 논문의 해석 품질이나 모든 대화의 선별 품질을 보장하지 않는다. CLI 자체의 기본 입력 부담은 남아 있으며, 작은 메모 요청도 수천 토큰이 들 수 있다. 자동 메모를 끄거나 작업 모델을 바꿀 수 있다.

자동 검사: TypeScript/Vite build, 전체 core, Product UI, Notes UI. 새 검사는 원문 번호·예산·캐시·표시 재실행·작업별 모델 설정, 의미 있는 수정·공백·삭제·모델 실행 중 수정·실패 보존, 빠른 후속 대화·보관함 범위·중복 방지를 포함한다. 실행 파일 패키징·내부 파일 일치·실제 실행도 별도 검증한다.

## 이전 리뷰에서 함께 반영된 내용

질문 범위와 명시적 페이지 근거, 최대 8편·전체 입력 제한, 실제 사용량과 입력 구성 표시, 짧은 일회성 CLI 지침, 최종 번역 프롬프트 24,000자 제한, 페이지 범위 재번역과 범위 밖 캐시 보존, Codex 문맥 정리, 중복 AI 작업 차단, 읽음 후 연결 후보 진입점, 명시적 이해 상태, 무료 보관함 정리, 대화·첨부·근거 메모 초안 복원, 대화 파일 원자적 저장·백업, Windows CLI shim 호환성을 유지한다.

세부 구현과 이전 CLI 비교 수치는 `product-completion-2026-09-10.md`에 있다. `main-parity-context-audit-2026-09-10.md`는 최초 판단 기록이며 구현 완료 보고서는 아니다.

## 한 번에 확인할 체크리스트

익숙한 논문 1편으로 아래 세 묶음을 확인하면 된다. 저장·재실행·보호·범위 같은 기계적 동작은 자동 검사를 했으므로, 사용자에게는 **내용 선택과 사용감**을 중심으로 요청한다. AI 사용이 표시된 동작에는 선택한 CLI 사용량이 든다.

### A. 읽기·번역·첫 노트

- [ ] 처음 열고 잠시 기다린 뒤 하이라이트를 본다. **정말 중요한 곳을 골랐는지, 놓친 핵심은 무엇인지** 평가한다. 기존 캐시가 있으면 ‘핵심 안내 다시 만들기’를 한 번 사용한다. AI 사용.
- [ ] ‘핵심 읽기 안내 → 읽기 노트 열기’. **요약과 발견·방법·한계가 다시 읽을 때 도움이 되는지**, 장황하거나 당연한 말은 무엇인지 기록한다.
- [ ] 하이라이트를 켜고 끄며 **원문 가독성을 해치는지** 본다. 해당 노트의 원문 링크가 판단을 검증하기 편한지도 본다.
- [ ] 현재 페이지 재번역 1회. 부정·수치·단위·주장 강도와 작은 피겨 글자를 원문과 비교한다. ‘정확함 / 의미가 바뀜 / 읽기 불편’으로 평가한다. AI 사용.

### B. 나에게 남기는 메모·노트 구성

- [ ] 평소처럼 “이 논문 요약해줘”, “고마워”처럼 대화한 뒤, **불필요한 메모가 늘어나는지** 본다.
- [ ] 실제 연구에 적용할 계획과 아직 헷갈리는 지점을 말한다. 답변 뒤 잠시 기다렸다가 ‘나에게 남길 것’에서 **남겨야 할 내용이 빠졌는지, 너무 많이 저장했는지** 본다. 채팅·선별 메모 AI 사용.
- [ ] 그 의문을 이해했다고 명시적으로 말한다. **해결된 의문이 남아 있거나, 여전히 필요한 연구 계획까지 사라지는지** 본다.
- [ ] AI가 만든 문장 하나를 자기 말로 고치고, 별도 문장을 하나 추가한다. 이후 한 번 더 관련 대화를 한다. **고친 내용과 새 AI 메모가 자연스럽게 함께 읽히는지** 평가한다. 보존 자체는 자동 검사 완료.
- [ ] 노트를 닫았다 다시 본다. **첫 화면에서 필요한 정보를 바로 찾는지, 접힌 목록을 얼마나 자주 펼치는지, 앞으로 이 노트를 다시 열 것 같은지** 답한다. 대안 디자인을 직접 만들 필요는 없다.

### C. 설정·기존 지식 흐름·긴 대화

- [ ] 설정 왼쪽 탭에서 처음 읽기·번역·대화 메모리·지식 정리·구조 분석을 찾아본다. **항목 이름만으로 모델이 어디에 쓰이는지 이해되는지** 본다. 모델을 바꾸기만 하는 것은 AI 호출이 아니다.
- [ ] 논문 노트에서 ‘아직 모르겠음 · 메모’ → ‘이해함’ → 읽음 상태의 연결 후보 생성을 확인한다. **개인 메모와 상태 표시의 차이, 승인 전 후보라는 점이 명확한지** 본다. 연결 후보 생성은 AI 사용.
- [ ] 길어진 Codex 대화가 있으면 문맥 정리 후 앞서 논의한 방법·한계를 한 번 질문한다. **중요한 조건을 잊었는지** 평가한다. 문맥 정리·후속 질문은 AI 사용. 긴 대화가 없으면 지금 억지로 만들 필요 없다.

응답 양식: `A/B/C: 괜찮음 또는 문제 / 논문·쪽 / 행동 / 기대 / 실제`. 메모 선별 문제는 해당 사용자 발언과 잘못 남은·빠진 항목만 함께 주면 된다. 급한 문제가 아니면 전부 모아서 한 번에 답하면 된다.

## 남은 한계

- 선별은 한국어·영어의 로컬 신호와 모델 판단을 조합한다. 암시적인 표현이나 다른 언어의 중요한 발언은 놓칠 수 있다. 앱 종료 전에 처리하지 못한 대화를 재실행 때 유료 작업으로 소급 처리하지 않는다.
- 보호된 사용자 문장은 AI의 최대 6개 제한 때문에 지우지 않는다. 사용자가 많이 고쳐 쓰면 노트가 6개 항목보다 길어질 수 있다.
- 턴 사이 동일 원문 근거 생략, 이미지 자동 축소, CLI 전역 설정 완전 분리, 대화별 증분 저장은 이전 판단대로 후속 작업이다. 현재는 원문 정확성과 기존 데이터 보존을 우선한다.
- Mac 실제 기기 사용성, 배포 서명·공증·자동 업데이트와 공개 출시 승인은 별도다. CI 패키징 성공을 실제 사용성 승인으로 보지 않는다.
