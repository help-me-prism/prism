# 번역 상태와 아래첨자 보존

이 회차는 이전의 코드 변경·실화면 검증을 진행으로 분류하고, 남아 있던 과학 표기 손실을 실제 공학·생물학 논문으로 추적했다.

## 사용 중 발견한 문제

- 생물학 논문 2쪽은 영어 원문인데 패널에 ‘한국어 · 저장됨’이 보였다. 다른 페이지에 캐시가 있다는 사실을 현재 페이지의 번역 완료로 표시한 오류였다. 현재 페이지의 실제 번역 문장 수를 계산해 ‘번역 전 · 원문’, 일부 번역 문장 수, 페이지 번역 완료를 구분한다.
- 공학 논문 4쪽의 `m₀`, `ρ₀`가 PDF.js 문자열에서 `m0`, `ρ 0`으로 평탄화됐다. 이 문자열이 번역뿐 아니라 질문 근거와 노트에도 그대로 전달됐다. 문자열 정규식으로 첨자를 추측하면 일반 숫자·각주까지 잘못 바꿀 수 있다.

## 구현

PDF의 실제 글자 그리기 기록과 원문을 정확히 대응시킨 뒤, 기준 문자보다 작은 글꼴과 낮은 기준선, 인접한 글자 원점을 모두 확인한 아래첨자에만 별도 메타데이터를 만든다. 기존 원문·ID·해시는 유지한다. 위첨자는 각주와 구분할 추가 근거가 없으므로 자동 변환하지 않는다.

검증된 표기는 요청별 보호 토큰으로 번역 모델에 전달한다. 응답의 누락·중복·다른 문장 토큰을 검사하고, 저장 전 원문 문자열로 복원한다. 잘못된 한 문장이 다른 정상 문장의 저장을 막지는 않는다. 새 검증 정보와 맞지 않는 옛 번역 캐시는 재사용하지 않는다.

번역 화면은 모호하지 않은 대응 위치에 원문 글자 조각을 인라인으로 표시한다. 글자 기준선도 보존한다. 직접 선택한 질문 근거와 자동 선정 근거, 노트의 인용문에는 같은 검증 결과의 수학 표기를 사용한다. 근거 카드의 명시적 인라인 수학은 안전한 KaTeX 설정으로 렌더링하며, 원문 이동과 내장 원문 메타데이터는 유지한다.

## 실제 환경 차이

첫 자동 검사에서 두 표기가 통과했지만 실제 Windows 화면에는 `m₀`만 나타났다. 독립 Chromium 렌더링으로 `ρ`의 이탤릭 잉크와 다음 숫자의 잉크가 겹치는 것을 확인했다. 잉크 경계를 글자 간격으로 사용한 오류를 수정해 실제 글자 원점의 전진을 확인한다. 작은 글꼴과 낮아진 기준선 조건은 유지했다. Chromium 캡처를 별도 회귀 fixture로 남겼다.

## 실제 모델 확인

공개 공학 논문 문장 두 개를 `gpt-5.6-luna`, low reasoning으로 한 번 번역했다. 두 문장 모두 보호 토큰 검사에 통과했다. 도구 실행은 0회였고, 입력 13,006토큰 중 캐시 8,960토큰, 출력 223토큰(추론 출력 113토큰)이 보고됐다. CLI 기본 컨텍스트도 포함된 수치이며, 문장 두 개의 본문 토큰만을 뜻하지 않는다. 이 결과를 격리된 검토용 보관함의 해당 두 문장에만 적용했다.

CLI 실행 방식은 [공식 비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode)의 JSON 출력·읽기 전용 실행과 대조했다. 이 작은 표본은 과학 표기 전달 검증이며, 여러 분야의 번역 용어·의미 정확성을 모두 승인하는 결과가 아니다.

## 검증 범위와 한계

실제 공학 PDF의 NAPI와 Chromium 글자 기록, 기준선·크기·배율·이탤릭 겹침, 일반 숫자·각주·누락 글꼴·잘못된 원문 정렬, 요청 토큰 누락·중복, 기존 캐시, 원문 해시 유지, 실제 임시 보관함 저장과 노트 수학 렌더링을 검사한다. 페이지 상태는 첫 페이지에만 번역 캐시가 있는 3쪽 PDF로 검사한다.

통합 빌드, 전체 core, Product UI, Notes UI가 통과했다. 실제 Windows 검토에서 [번역 본문의 두 아래첨자](images/round32-inline-final.png), [미번역 생물학 페이지 안내](images/round32-biology-status.png), 실제 메모를 저장한 [노트의 수학 근거 카드](images/round32-note-math-final.png)를 확인했다. 부모 담당도 캡처를 열어 확인했다. 노트 하단의 일반 출처 목록에 평문 변수가 남은 추가 피드백에 따라, 원문 해시가 일치하는 출처 미리보기와 질문 첨부 미리보기도 검증된 아래첨자를 표시하도록 연결했다.

마지막 빌드에서 전체 core·Product UI·Notes UI를 다시 통과했다. 독립 담당이 [하단 출처 목록의 아래첨자](images/round32-note-list-final.png)를 확인하고 근거 카드를 클릭해 공학 논문 4쪽 원문 문장88로 복귀하는 것과 노란색 강조를 확인했다. 이 마지막 동선에서는 추가 저장이나 AI 호출이 없었다.

현재 자동 보존은 확실한 짧은 변수의 숫자 아래첨자에 한정된다. 모든 인라인 수식·복합 단위·위첨자·화학식을 해결하지 않았고, 스캔 PDF의 OCR 품질을 검증한 것도 아니다. 모호한 원문은 추측하지 않는다. 전체 제품 목표는 계속 진행 중이다.
