# 지면 누락 복원과 질문 근거 확인

2026-09-10. 이전 루프는 원문 줄 간격을 참고하도록 실제 코드와 검증 결과를 변경한 진행이었다. 이번에는 최신 작업 트리 acd4b2a에서 출발해 남은 원문 요소 누락과 질문 준비 흐름을 검토했다.

## 화면에서 확인한 문제

독립 비평 담당이 Windows 격리 앱에서 좁은 좌우 비교와 채팅 → 번역 크게 → 문장 선택 → 비교 복귀를 조작했다. 페이지와 근거 첨부는 유지됐으나, 입력창의 `문장88 local-…` 표기로는 선택한 내용과 페이지를 바로 확인하기 어려웠다. 원문 전체는 기존 hover 툴팁에 있었으므로 미리보기가 전혀 없었던 것은 아니다.

번역 지면에는 표·피겨 캡션 아래 DOI 두 줄이 누락됐다. 원문 파서가 DOI를 번역 대상에서 제외하고, 지면 렌더러가 페이지 중간의 제외 항목을 복원하지 않기 때문이다.

## DOI 수정과 검증

DOI만 있는 PDF text item을 원문 픽셀로 다시 그린다. 이미 다른 영역에 포함된 항목, 중복 항목, DOI를 언급하는 일반 문장은 추가하지 않는다. 기존 번역·앵커 ID를 변경하거나 AI를 다시 호출하지 않는다.

실제 공학 논문의 표·피겨 DOI와 하단 출판사 문구 좌표를 공개 CC BY fixture로 보존했다. 확대 비례와 기존 영역 중복 방지를 검사하고, Product UI에서 DOI 캔버스에 불투명한 원문 글자 픽셀이 존재하는지도 검사한다.

별도 비평 담당은 새 빌드의 같은 약 481px 폭 지면에서 표의 `/t001`과 피겨의 `/g002`가 복원됐음을 확인했다. 부모 담당도 캡처를 다시 열었다. 해당 표·캡션 아래에 놓이고, 이 화면에서 새 잘림이나 겹침은 보이지 않는다. 원문과 완전히 동일한 조판을 달성했다는 뜻은 아니다. PDF가 URL을 여러 조각으로 분할한 경우까지 복원하는 기능은 아직 검증하지 않았다.

## 질문 입력창

기존 근거 라벨 옆에 페이지·종류·원문 발췌를 표시한다. 전체 논문 제목과 발췌는 툴팁 및 접근성 설명으로 제공한다. 긴 발췌는 한 줄로 제한하며 기존 110px 입력창 최대 높이와 스크롤을 유지한다. 그림의 내부 저장 경로와 좌표는 사용자 발췌에서 숨기고 캡션 또는 `선택한 피겨 영역`을 표시한다. 모델에 전달하는 근거 자체는 변경하지 않는다.

통합 Product UI 검사에서 피겨의 내부 저장 경로가 발췌에 노출되는 실패를 발견해 고쳤다. 이후 검사에서는 페이지·종류·비어 있지 않은 발췌·내부 ID 미표시·입력창 너비 안 배치와 기존 이미지 첨부·삭제·전달 경로가 통과했다. 전체 core 검사, 추가한 최종 발췌 helper 검사, 최종 빌드도 통과했다. 실제 AI 답변 품질과 macOS 실기 사용성은 이번 검사 범위 밖이다.

[DOI 복원 화면](images/round28-doi-restored.png)

독립 화면 검토에서 5개 문장을 담고 마지막 항목까지 스크롤한 뒤 중간 한 개를 삭제했다. 남은 4개 근거와 입력한 질문은 비교 보기로 돌아온 뒤에도 유지됐다. 피겨 칩은 자동 검사로 확인했으며 이번 수동 검토는 문장 칩을 대상으로 했다.

이 과정에서 긴 질문을 붙여넣으면 끝부분이 가려지는 추가 결함을 발견했다. 선택 내용을 건드리지 않고 현재 커서가 입력창 안에 보이도록 스크롤한다. 붙여넣기가 빈 줄로 끝나 Chromium의 커서 Range가 빈 사각형을 반환하면 해당 빈 줄의 블록 위치를 사용한다. 마지막 빈 줄이 실제 스크롤 영역 안에 보이는 자동 검사와 기존 첨부 전달 검사가 최종 빌드에서 통과했다. 개행 없는 긴 질문 끝이 수동 휠 없이 보이는 것도 독립 화면 검토로 확인했다.

마지막 빌드의 수동 재검토에서도 근거 2개 뒤 긴 한국어 질문과 마지막 개행을 붙여넣었을 때, 수동 휠 없이 마지막 문장과 그 아래 빈 줄 커서가 입력창 안에 보였다.

추가 AI 호출이나 실제 질문 전송은 하지 않았다. 길게 붙여넣은 질문은 격리된 회귀 검토용 초안이다. 좁은 지면 자체의 가독성과 전체 글꼴 취향에 대한 합격 판정은 아니다.
