# Note preservation and explicit source navigation

This round adds independent draft/before snapshots and preserves the displaced original inode during note replacement. Publication uses an exclusive hard link: a competing external file is never overwritten as a fallback. The live note and the requested draft have independent inodes, so later edits do not mutate the retained draft. Reads wait for in-process note writes and tolerate the short missing-path interval during replacement.

Saved history is available from the note menu, with a full readonly preview and explicit restoration. Restoring first saves dirty current content and retains the displaced version. History and follow-up reads carry the original vault token; a vault switch remounts the document. Initial deterministic section updates finish before exposing the editable document, avoiding a first-keystroke conflict with Prism's own opening write. Failed reads now offer a retry instead of an indefinite loading message.

A separate recovery inventory finds interrupted transactions with no live Markdown file, without relying on an indexed node. Pending publication is not silently treated as a successful or failed save: the researcher previews a preserved version and explicitly restores it. Existing destination files are never replaced. IDs are matched against the current vault's authoritative inventory; junctions outside the vault and foreign-vault IDs are rejected.

Validation so far: production build, full core suite, targeted missing-note vault integration, and the full Notes UI suite passed. The UI test creates two real edited versions, restores an older version and finds the displaced current content in history; it also seeds an actual publishing journal with no target or indexed node and restores the exact selected text through the dialog. The first recovery UI run exposed a test-only reload race; waiting for the new JavaScript context fixes it. The separate-process late-write test proves the original open inode remains available in displaced.md. File-symlink race coverage is skipped on this local Windows account because file symlink creation lacks privilege; directory-junction tests do run.

Limitations: hard-link-incompatible filesystems fail closed; histories currently grow without automatic pruning; changing a note filename can hide earlier basename-associated history. This is not a guarantee of capturing every intermediate external-editor state or surviving every power-loss boundary. Broader Obsidian stress and physical macOS use remain outstanding.

The previous macOS ARM CI exposed an explicit-source navigation race: a remembered page could replay after jumping to a saved figure. Explicit anchors now own layout-driven restoration until the user navigates. A strict local product test then exposed page 3 followed immediately by a format change replaying page 1 before the navigation-settle timer. Format/zoom transitions now prefer the active navigation target and discard superseded timer callbacks.

Final validation: the strict product UI suite passes the saved-figure center and immediate page/format change scenarios. The rebuilt final backend passes the full core suite, including unsupported-link preflight (live original retained), an already-conflicting submitted draft retained in history, and missing-note vault integration. The final Notes UI suite passes history/orphan recovery, Notes-local settings, cross-window dark/light synchronization, and keyboard focus restoration. No AI calls were made in this round.

A native reviewer recovered the missing fixture, compared alternative versions, edited the restored note and restored an earlier version. The displaced newer edit remained readable in history. History was checked in light and dark themes; the recovery dialog was checked in dark. See [native review](round14-native-notes.md) and [privacy-safe history dialog capture](images/round14-history-light.png). Native review identified awkward access to theme settings from Notes; the existing bottom rail button now opens Notes settings for appearance and an explicit folder choice. The mocked directory picker in the isolated native fixture is not evidence of real OS folder-dialog behavior.

Before replacing the live file, an exclusive-link probe now checks the actual destination directory. Failure leaves the original name intact and retains the draft, rather than discovering an unsupported filesystem only after capture. Permissions or transient failures after the probe still use the guarded recovery paths; the probe is not a universal filesystem guarantee.
