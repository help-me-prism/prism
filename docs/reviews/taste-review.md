# 독립 시각 품질 심사 — 2026-09-09

담당: 구현과 분리된 시각 품질 심사 에이전트. 사용자가 제공한 이전 버전 스크린샷과 `tmp/ui/round4`의 실제 화면 세 장을 직접 확인했다. 아래의 인상 평가는 주관적 디자인 판단이며, 배율·줄바꿈·원문 대응에 대한 항목은 관찰 가능한 결함이다. 아직 새 빌드의 네이티브 화면은 심사하지 않았다. 인간 사용성 연구나 사용자 취향의 대체라고 주장하지 않는다.

**현재 판정: 반려.** 차분한 색상만으로 완성도 높은 논문 리더가 되지 않는다. 현재 화면은 논문 본문과 수식의 활자 크기가 따로 놀고, 제어 요소의 위계가 희미하다. 번역문이 원문 칼럼에 붙여 넣은 웹 에세이처럼 보인다는 것이 내 시각적 판단이다. 이 상태에서 `원문 형식`이라는 이름은 기대를 충족하지 못한다.

코드 근거도 확인했다. `PaperTranslationLayout.tsx`의 페이지 폭 기반 `max(12, min(16, width / 45))`가 원문 본문 크기와 관계없이 번역문 크기를 정한다. 480px 종이에서 원문 글자가 약 7px이면 한국어 12px 최저값은 큰 비례 차이를 만든다. `styles.css`는 Inter/Pretendard를 선언하지만 현재 확인한 번들 폰트는 Noto Serif KR뿐이다. 선언만으로 운영체제 간 활자 일관성이 보장되지 않는다. 이 사실들이 위 시각적 문제의 원인을 일부 설명한다.

## 이전 화면에서 보존할 것

사용자 스크린샷의 가치는 베이지색이나 작은 버튼이 아니다. 양쪽 논문이 같은 실루엣이고, 같은 소제목 아래 같은 수식 번호가 보이며, 본문과 수식의 활자 비례가 유사하다. 읽다가 우측 번역을 보고 좌측 근거로 되돌아가는 공간 기억이 유지된다. 이 구조적 대응을 우선 회복한다. 이전 화면의 많은 툴바와 빈 채팅 창까지 모방할 필요는 없다.

## 다음 화면을 승인할 최소 조건

1. **동일 조건 비교:** 같은 원문 페이지와 같은 실제 페이지 폭으로 원문/번역을 나란히 캡처한다. 한 화면만 확대해 놓고 개선이라 판정하지 않는다.
2. **원문 상대 크기:** 일반 본문, 제목, 캡션의 위계가 보존되고 본문과 디스플레이 수식의 시각적 활자 크기가 크게 다르지 않는다. 한국어를 위한 소폭 증가는 허용하지만 1.5배 이상인 경우 원인과 대안을 다시 검토한다. 수치만으로 합격시키지 않는다.
3. **문서의 골격:** 원문 여백과 칼럼, 소제목, 수식 번호, 표·피겨 순서가 즉시 대응한다. 한국어 길이에 따른 수직 확장은 허용하되, 불필요한 UI 머리말이나 성긴 행간이 페이지를 늘리지 않는다.
4. **깨지지 않는 본문:** 이상한 한 글자 줄, 수식·표의 일부 누락, 임의 잘림, 겹침, 노출된 미완성 LaTeX는 한 건도 허용하지 않는다. 번역되지 않은 곳은 원문 픽셀로 남긴다.
5. **일관된 활자:** 한글·영문 UI의 높이와 무게가 한 체계로 보인다. macOS 확인 전에는 두 운영체제 활자 검증 완료라고 말하지 않는다.
6. **읽기 우선 화면:** 원문/번역 모드 조작이 중복되지 않고, AI 설정·사용량·동기화 상태가 본문보다 시선을 끌지 않는다. 주 액션과 단순 상태를 첫눈에 구별한다.
7. **실제 화면 재심:** 1280×900과 넓은 화면, 밝은/어두운 테마, 1단/2단 논문, 수식/표/멀티패널 그림을 본다. 확인하지 않은 조합은 미검증으로 남긴다.

현재 변경 제안이나 통과한 자동 테스트는 이 심사 결과를 바꾸지 않는다. 실제 새 화면을 확인한 뒤 아래에 별도 판정을 추가한다.

## UI 글꼴 수정 — 화면 심사 전

부모 에이전트가 문서 조판을 담당하고, 이 심사 에이전트에 한정적으로 UI 글꼴 구현을 위임했다. 따라서 내가 변경한 UI 글꼴도 별도 UX/UI 에이전트의 교차 심사가 필요하다.

- 공식 `pretendard@1.3.9`를 고정한 빌드 의존성으로 추가하고 한국어·라틴을 포함한 약 2MB 가변 WOFF2를 앱 안에 묶었다. CDN이나 사용자 컴퓨터의 설치 여부에 의존하지 않는다. [공식 배포·라이선스 설명](https://github.com/orioncactus/pretendard/blob/main/packages/pretendard/docs/en/README.md).
- `src/typography.css`에서 UI 글꼴 체계를 통일했다. 주요 조작은 12px, 보조 상태는 11px, 탐색 항목은 13px, 채팅 본문은 14px/1.75로 조정했다. PDF 픽셀·번역 문서 활자·수식·코드 서체는 수정하지 않았다.
- 배포 파일에 포함되는 `public/licenses/Pretendard-OFL.txt`에 공식 v1.3.9 라이선스를 보존했다.
- 설치 시 npm audit 결과는 0건이었다. 빌드 및 실제 화면은 아직 미검증이며, 조작 글자를 키우면서 툴바가 더 빽빽해지지 않았는지 특히 재확인해야 한다.

## Round 5 실제 화면 재심

PID 17112, CDP 9351의 새 Prism 빌드를 Windows 네이티브 `sky`로 조작했다. 1280×900, 어두운 테마, engineering-foamed-concrete p1–5, 기존 p4 번역 캐시만 사용했다. 새 AI 요청은 없었다. 각 조작 후 실제 화면을 다시 읽고, 렌더링 중간 장면은 안정된 화면으로 재확인했다.

**판정: 문서 골격 개선은 확인. 완료 승인은 보류.** 한국어 본문만 커지는 이전 비례 오류가 크게 줄었다. 표 → 본문 → 수식 1 → 본문 → 수식 2 → 본문 → 피겨 → 캡션이라는 원문 구조가 비교 화면에서 바로 보인다. 불필요한 종이 내부 UI 머리말은 사라졌고 캡션의 불필요한 줄바꿈도 해소됐다.

### 실제 조작과 결과

- 기존 비교+채팅 p1에서 채팅을 닫고, 동기화가 켜진 채로 다음 페이지를 세 번 눌렀다. p2, p3, p4의 원문/번역/번역 범위가 모두 일치했다.
- p4를 한국어 단일 보기로 바꿨다. 약 1000px 종이가 독서 공간을 채우며 본문과 수식의 크기 비례가 자연스러워졌다.
- p4 단일 → 채팅 열기 → 비교 → 단일의 안정된 화면에서 p4가 유지됐다. 이전 round 4의 p6 이동 오류는 이 경로에서 재현되지 않았다.
- 아래 피겨까지 스크롤한 뒤 비교로 전환했다. 같은 p4가 보였지만 양쪽 피겨의 화면 높이는 약 150px 달랐다. 정확한 문단·피겨 위치의 대응은 더 개선할 여지가 있다. 다음 페이지는 양쪽 p5와 번역 범위 p5로 정상 이동했다.

### 남은 반려 사유

1. **P1 원문 글자 잔해:** 원문 헤더 아래, 첫 번역 캡션 위에 영어 글자의 잘린 아랫부분/윗부분 같은 가로 조각이 남는다. p2/p3의 첫 본문 부근에서도 비슷한 조각이 보인다. 원문 보존 띠의 크롭 경계가 첫 글자를 가로지르는 것으로 의심된다. [1000px 단일 보기](../../tmp/ui/round5-taste/engineering-p4-single.png)의 표 1 위 y≈340에서 분명하다.
2. **P1 확대된 원문 시각 요소의 선명도:** 같은 단일 보기에서 한국어는 선명한데 표·수식·머리말은 상대적으로 흐리다. 번역 종이를 키울 때 원문 캔버스의 해상도도 맞춰야 한다. 비례 문제와 별개다.
3. **P2 좁은 비교:** 채팅을 켠 비교에서는 종이가 각각 약 290px로 작아 실독서가 어렵다. 확대를 강제하지 않고도 단일 보기/상하 보기/라이브러리 접기 등의 명료한 복구 경로가 필요하다. [p4 비교+채팅](../../tmp/ui/round5-taste/engineering-p4-chat-compare.png).
4. **P2 조작부 밀도:** 글꼴은 전보다 통일됐지만 탭·본문 모드·번역·배율의 네 층과 반복 라벨은 여전하다. 서체 교체만으로 이 구조 문제를 해결했다고 볼 수 없다.
5. **P2 번역 본문의 농도:** 한국어 명조가 동일 축척의 원문 본문보다 가볍게 보인다. 현재 비교 크기에서 특히 회색처럼 보이는 인상이다. 원문과 비슷한 무게를 위한 소폭 조정은 가능하지만, 선명도 수정 후 다시 판단해야 한다.

부모가 1·2의 수정에 착수했다는 메시지는 받았으나 수정 후 빌드는 아직 심사하지 않았다. UI 글꼴 변경은 내가 구현했으므로 별도 UX/UI 담당의 교차 심사도 필요하다. 밝은 테마·macOS·넓은 화면·다른 분야 논문은 이번 재심에서 미검증이다.

## Round 5 최종 정적 교차 확인

네이티브 화면 제어는 별도 UX/UI 담당에게 둔 채, 새 [선명도 수정 화면](../../tmp/ui/round5/engineering-p4-crisp-dark.png)을 직접 열어 앞선 단일 화면 및 같은 채팅 열림 상태의 피겨 화면과 비교했다. 최신 화면은 약 633px 종이이고 이전 단일 화면은 약 1000px이므로 두 이미지만으로 확대 선명도를 같은 조건에서 비교했다고 주장하지 않는다. 같은 폭인 이전 채팅 열림 화면의 수식·그림도 함께 확인했다.

**범위를 한정한 판정: 이번 활자·문서 골격 수정은 수용한다.** 최신 engineering p4 화면에서 다음이 보인다.

- 첫 캡션 위에 있던 영어 글자 잔해가 사라졌다. 머리말·표·본문의 시작이 정상적인 논문처럼 보인다.
- 같은 폭의 이전 채팅 화면보다 분수·첨자·수식 번호와 그림 내부 선이 선명하다. 표의 행과 글자도 번진 이미지 인상을 벗어났다.
- 한국어 본문과 수식이 한 문서의 활자 비례로 보인다. 원문 표·본문 칼럼·수식 번호의 위치 관계를 유지하고, 원문 대신 웹 에세이를 끼운 듯했던 초기 인상은 해소됐다.
- 문서 조작부가 세 층으로 줄고 모드가 `원문 / 한국어 / 비교`, 그 다음 메모·번역·더보기로 정리됐다. 작은 버튼이 반복되는 설정 화면 같은 인상이 줄었다. 한국어·영문 UI 글꼴도 한 체계로 보인다.

잔여 취향상 개선점은 한국어 명조 본문의 획이 다소 가볍다는 점과, 모델·사용량 영역이 여전히 채팅 상단에서 제법 넓은 공간을 차지한다는 점이다. 둘 다 지금의 원문 형식 회복을 반려할 정도의 결함으로 보지는 않는다. 본문 무게를 조정한다면 전체 서체를 다시 교체하기보다 작은 무게 차이를 같은 페이지에서 비교하는 정도가 적절하다.

이 판정은 해당 어두운 테마의 engineering p4 화면에서 활자 비례·문서 골격·UI 인상을 확인한 결과다. 비교 팝업 조작, 다른 화면 크기·운영체제, 논문 전체 또는 전 분야 레이아웃의 합격 판정은 아니다. 최신 팝업의 실제 조작 확인은 별도 UX/UI 담당의 결과를 따른다.

## 사용자 불만 재접수 후 독립 재평가

이전의 “이번 수정 수용”을 기준점으로 삼지 않고 [현재 비교 화면](images/reader-comparison-dark.png)을 다시 읽었다. 네이티브 UI는 다른 담당자가 사용 중이므로 조작하지 않았다. **현재 화면을 완성된 출판물 수준의 번역 조판이라고 승인하지 않는다.** 앞선 수정 수용은 잔해·흐림·과도한 본문 확대가 해결됐다는 제한된 의미였다. 사용자가 여전히 글씨와 원문 형식에 불만을 느끼는 데에는 화면상의 근거가 있다.

### 지금 가장 먼저 고칠 세 가지

1. **한국어 본문의 농도와 획 무게.** 원문 본문은 조밀하고 검은데 한국어는 얇은 회색 글자로 보인다. 동일한 크기 체계가 됐어도 독서의 질감은 아직 다르다. 코드에서 번역문 색은 어두운 `#28332e`이지만 실제 명조 획이 가늘어 축소 화면에서 흐리게 보인다. 색상값만 보고 충분하다고 판단하면 안 된다. 같은 원문 페이지·같은 폭에서 명조 400/450/500 정도를 비교하고 본문·영문 변수·수식의 체감 농도를 맞추는 검증이 필요하다. 새 서체 이름을 추가하는 것보다 이 비교가 우선이다.
2. **원문의 강조 위계 손실.** 원문 표 캡션의 굵기와 문단 시작의 강조가 번역문에서 평평해진다. 현재 블록 크기 추정은 있지만 본문 내 강조를 함께 전달하는지는 이 화면에서 확인되지 않으며, 실제 캡션은 가늘다. 제목/캡션/본문을 구분하는 범용 CSS에 더해 원문의 굵기·강조를 보존하는 정책이 필요하다. 한국어 전체를 무작정 굵게 만드는 것은 대안이 아니다.
3. **정확한 형식 보존의 수준을 과장하지 않기.** 같은 약 481px 종이 폭에서 원문 그림 시작은 y≈581, 번역은 y≈622이며, 페이지 하단은 각각 y≈796와 y≈871이다. 번역 종이가 약 12% 더 길다. 구조 대응은 개선됐지만 사용자 예시의 같은 실루엣과는 차이가 있다. 번역 길이에 따른 확장은 합리적일 수 있으나, 부풀려진 여백이나 헤더/풋터 중복에서 온 차이인지 먼저 분리해야 한다. 서로 같은 높이의 페이지라고 설명해서는 안 된다.

UI 자체는 이전보다 조용하지만, 활성 논문의 파일명이 제목 막대·탭·사이드바에 반복되고 원문 하단에는 PDF의 `4/17`과 앱의 `4`가 함께 보인다. 이것은 당장 조작을 막는 문제보다는 정리되지 않은 제품 인상을 주는 잔여 요소다. 파일명 대신 실제 논문 제목·저자 정보를 안정적으로 보여주는 개선도 한층 더 중요하다.

다음 p11 화면에서는 이런 인상 평가와 별개로 원문 도형·수식·표·강조·순서가 빠짐없이 유지되는지 확인한다. 아직 그 화면을 보지 않았으므로 p4의 결과를 다른 페이지로 확대하지 않는다.

## 본문 450·원문 강조 반영 후 확인

[새 p4 실제 화면](../../tmp/ui/precise-p4-fontweight.png)을 위의 기존 비교 화면과 같은 뷰포트·페이지 폭에서 직접 비교했다. 네이티브 조작은 하지 않았다.

**판정: Noto Serif KR 450 / `#171717` 조정은 유지하는 것이 낫다.** 기존의 옅고 씻긴 듯한 인상이 줄고, 한국어 본문과 검은 수식이 한 문서로 보인다. 원문에서 가져온 굵기 700의 표·그림 캡션도 이 p4에서는 과하게 굵지 않다. 제목/캡션의 위계가 전보다 명료하다. 현재 본문은 원문보다 여전히 가벼운 편이나, 이를 이유로 본문 전체를 더 굵게 만들 필요는 없어 보인다.

이 변경은 글자의 농도와 강조를 개선한 것이다. 문단 길이와 그림의 수직 위치 차이는 거의 그대로이며 형식 문제까지 해결한 것으로 확대해서는 안 된다. 약 480px 비교 종이는 지속 독서하기에 작다. 이 문제는 더 굵은 글자보다 단일 보기·전체 페이지 확대·대응하는 문단 확대 등 읽기 동작으로 해결해야 한다. 다른 페이지의 굵기 메타데이터가 잘못 분류되지 않는지는 별도 확인이 필요하다.

부모가 확인한 현재 동작상 이 1280px 화면은 사용자가 명시적으로 선택한 좌우 비교이며, 좁은 초기 화면은 상하 비교를 기본으로 하고 명시적인 선택은 유지한다. 따라서 여기서 작은 글자는 좌우 비교의 지속 독서 한계로 기록한다. 이미 있는 단일·상하 보기로 전환할 수 있으므로 굵기를 더 올리거나 명시적인 비교 선택을 강제로 바꿀 이유는 아니다. 이 초기 기본값은 이번 정적 이미지 심사에서 직접 조작 검증하지 않았다.

## p11 문장 단위 원문 보존 확인

[현재 p11 비교 화면](../../tmp/ui/precise-p11-korean-comparator.png)을 [이전 문단 전체 원문 유지 화면](../../tmp/ui/final-p11-intact-paragraph.png)과 비교했다. 실제 번역 실행량 16/16과 유니코드 손상 문장 1개 보존은 부모가 제공한 실행 정보이며, 이 심사는 화면의 연속성·가독성만 확인했다.

**범위 한정 판정: 문장 단위 보존은 문단 전체를 영어로 남기던 결과보다 유용하다.** 보존 문장 앞뒤의 한국어는 충분히 읽히고, `S ≥ 1.2`를 포함한 영어 문장의 기호·본문은 잘리지 않고 보인다. 비교한 부분에서 본문의 순서나 겹침 문제는 보이지 않는다. 모르는 기호를 추정 번역해 매끈하게 보이는 것보다 과학적 내용을 그대로 남기는 이 처리가 타당하다.

다만 시각적으로 완전히 자연스러운 문단은 아니다. 보존한 영어 첫 줄 `Compared with the FC without`이 원문의 줄 중간 위치를 유지해 오른쪽에서 갑자기 시작하고 다음 줄은 왼쪽으로 돌아간다. 독자는 떠 있는 문장 조각처럼 느낄 수 있다. 내용 손실 문제는 아니지만, 한 문장만 원문으로 남았다는 작은 상태 표시와 원문 발췌임을 이해할 수 있는 표현이 있으면 덜 어색하다. 추후 줄별 원문 픽셀을 안전하게 다시 정렬할 수 있다면 이 비정상적인 첫 줄 들여쓰기도 다듬을 수 있다.

현재 `11쪽 번역됨`만으로는 일부 문장이 원문이라는 사실을 설명하지 않는다. 번역 보기 상태에 `1문장 원문 유지` 같은 정확한 정보를 제공하는 편이 신뢰에 맞다. 이는 전체 문단을 다시 원문으로 돌리거나 손상된 기호를 추정 번역해야 한다는 뜻이 아니다.

이 정적 화면은 p11 본문의 일부다. 페이지 전체 피겨·표·하단 문단, 다른 페이지, 모든 언어 조합의 승인을 뜻하지 않는다. 이번 본문 내 보존 부분에 한해서 내용 보존과 읽기 가능성을 확인했다.
