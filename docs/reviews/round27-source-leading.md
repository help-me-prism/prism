# 원문 대비 번역 지면 재심

2026-09-10. 사용자의 글꼴·원문 형식 불만에 따라 구현 담당과 별도 시각 비평 담당이 기존 논문 캐시를 사용해 검토했다. AI 취향 판정이나 자동 테스트 통과를 사용자 만족의 대체로 삼지 않는다.

## 관찰과 수정 기준

- 같은 폭의 engineering p4에서 한국어 문단의 행간이 더 크다. 실제 PDF의 본문 10pt, 줄 간격 약 13pt에 비해 번역은 10.8pt × 1.48 = 15.984pt였다. 글꼴 이름을 바꾸는 것과 별개인 조판 문제다.
- 명확한 세 줄 이상의 한 문단에서만 원문 줄 간격을 추정한다. 한국어 최소 행간 1.35를 유지하며, 크기가 섞이거나 줄 간격·칼럼이 불확실하면 기존 값으로 돌아간다. 수식·표·피겨 픽셀과 텍스트 재배치 보기에는 적용하지 않는다.
- 비교 화면의 종이가 좁아지면 확대 읽기 제어가 이미 있어도 발견하기 어렵다. 이는 행간 수정만으로 해결되지 않는 UX 문제다.
- 표와 피겨 캡션 아래 DOI 행은 번역 지면에서 빠져 있다. 머리말의 PLOS ONE은 실제로 보존되어 있다. 비평 담당의 최초 로고 누락 주장은 부모 담당이 이미지로 확인하여 반박했고, 비평 담당도 철회했다.

## 심사 방식

원문과 번역을 같은 종이 폭으로 비교한다. 문단·제목·표·수식 위치, 본문과 수식의 활자 비례, 글자 잘림과 겹침, 조작부의 읽기 방해를 각각 확인한다. 미감은 판단의 이유를 제시하고, 관찰 가능한 누락과 구분한다. 실제 새 화면을 보기 전에는 수정 합격을 선언하지 않는다.

참고한 서비스 원칙은 [Linear의 일관된 헤더와 시각적 소음 축소](https://linear.app/now/behind-the-latest-design-refresh), [Readwise Reader의 읽기 화면 설정](https://docs.readwise.io/reader/docs/faqs/appearance)이다. 이 서비스의 색이나 서체를 복사했다는 의미는 아니다.

## 수정 후 검증

`npm run build`, 전체 core 회귀 검사, Product UI 검사가 통과했다. 실제 공학 논문의 rho/첨자를 포함한 글자 좌표에서 추론이 적용되고, 불확실한 간격·다른 칼럼·혼합 글꼴 크기는 기존 행간을 사용하는지 검사했다. Product UI는 확대 시 행간도 종이·글자·피겨와 같은 비율로 변하는지 확인한다.

독립 비평 담당은 새 빌드를 불러온 Windows 격리 창에서 같은 약 481px 폭의 engineering p4를 재검토했다. 첫 문단 끝과 수식 1은 약 3px, 마지막 본문 끝은 약 6–7px 위로 당겨졌다. 변화는 작지만 문단 밀도가 원문에 조금 가까워졌다. 새 수식 겹침이나 글자 잘림은 관찰되지 않았고 피겨·페이지 하단 위치는 유지됐다. 부모 담당도 아래 실제 이미지를 열어 확인했다.

원문과 동일한 줄 수나 줄 위치를 달성했다는 뜻은 아니다. DOI 누락과 좁은 비교 화면 문제는 남아 있다. 전체 제품 미감, 모든 분야의 번역 품질, macOS 실기 사용성은 이번 심사로 승인하지 않는다. 기존 번역 캐시를 사용했으며 새 AI 추론은 요청하지 않았다.
