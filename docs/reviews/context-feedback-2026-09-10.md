# 첫 사용자 피드백 반영

## 반영 내용

- 논문 선택을 직접 변경한 뒤에는 자동 선택을 끈다. 모두 해제한 상태에서 새 대화를 시작하거나 논문 탭을 닫고 다시 열어도 논문을 다시 추가하지 않는다. 보관함을 바꾸면 새 보관함의 기본 선택으로 시작한다.
- 논문 수 0개는 이번 질문에 자동 논문 발췌를 넣지 않는다는 뜻이다. 직접 첨부한 근거와 같은 CLI 대화의 과거 기억까지 지우는 것은 아니다.
- CLI 연결을 확인하는 Prism 설정 상단에 ‘연결 및 설정’, ‘AI 사용 기록’ 탭을 추가한다. 기록 탭을 열면 자동으로 읽으며 추가 스크롤이나 ‘보기’ 클릭이 필요하지 않다.

## 자동 확인

빌드 및 Product UI 검사. 실제 앱에서 마지막 논문 선택 해제, 새 대화 시작, 논문 닫기/재열기 뒤 0개 유지, 다시 선택하고 페이지 질문 전송, 화면 안의 사용 기록 탭 접근과 기록 없는 상태를 검사한다. 유료 추론은 실행하지 않는다.

## 확인할 것

이전 Prism 창을 닫고 `release/context-feedback/Prism-0.1.0-Windows-x64.exe`를 연다.

1. 논문 선택을 전부 해제한 뒤 논문을 다시 열어도 ‘논문 0개’가 유지되는지.
2. CLI 연결 설정 화면 상단의 ‘AI 사용 기록’을 바로 찾을 수 있는지.

## 컨텍스트 설계 설명

현재 전체 논문을 매 턴 새로 첨부하지 않는다. 로컬 원문 캐시에서 직접 고른 문장/페이지와 질문 관련 발췌, 짧은 초록을 구성한다. 자동 발췌는 기본 9,000자, 직접 첨부가 있으면 3,000자 예산이며, 직접 근거는 건당 최대 4,000자다. 총 46,000자 전송 제한은 토큰 수가 아니다. 검색은 주로 어휘와 간단한 한국어 의도 규칙을 사용하므로 고급 의미 검색이나 필요한 근거를 반복 조회하는 완성형 검색 시스템은 아니다.

후속 방향은 ‘논문 전체 로컬 저장/인덱싱 → 짧은 개요와 질문 관련 원문 → 필요한 구간 추가 조회’다. 논문 전체 비판·종합 비교는 일부 발췌만으로 전체를 검토했다고 주장하지 않고 섹션별로 더 넓게 읽어야 한다. 짧은 논문은 전체 문맥을 재사용하는 방법도 평가할 수 있다. 같은 대화에 전체 텍스트를 매 턴 새 메시지로 덧붙이는 방식은 피한다.

Claude는 프로젝트 자료가 컨텍스트 한도에 가까워지면 RAG로 관련 문서를 검색한다고 설명한다: https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects

ChatGPT는 프로젝트의 업로드 파일/지침/소스를 대화에서 공유해 사용할 수 있다고 설명하지만 이 문서는 매 요청의 내부 컨텍스트 조립 방식을 공개하지 않는다: https://learn.chatgpt.com/docs/projects

OpenAI API의 prompt caching은 같은 입력 접두부와 대화 기록 재사용으로 계산/입력 비용을 줄일 수 있다. 이는 웹 프로젝트의 내부 구현을 증명하는 자료가 아니며, 불필요한 본문을 반복 추가해도 괜찮다는 뜻도 아니다: https://developers.openai.com/api/docs/guides/prompt-caching
