## 디자인 판단

[Linear의 UI 개편](https://linear.app/now/how-we-redesigned-the-linear-ui)의 정보 위계·밀도·일관성과 [Readwise Reader의 읽기·하이라이트·노트 흐름](https://docs.readwise.io/reader/docs/faqs/highlights-tags-notes)을 참고했습니다. 화면을 복제하지 않고, 논문 읽기에 맞게 낮은 채도의 중립색, 제한적인 녹색 강조, 명료한 한국어 행동 이름, 조용한 테두리를 적용했습니다.

- 라이트 / 다크 / 시스템 테마를 설정에서 선택하고 창 간 동기화합니다.
- 인쇄물의 색 정보는 유지합니다. 다크 모드도 PDF·원문 발췌는 흰 지면입니다.
- 목록 글자 크기와 번역 행간을 높였습니다. 장식적인 AI 강조를 줄였습니다.
- 읽기 집중 모드, 설정 접기, 현재 화면을 가리키기만 하던 무동작 버튼 제거, 첫 화면의 강제 모달 제거를 적용했습니다.
- 모달의 Tab 이동을 내부로 제한하고 Escape 닫기 및 포커스 복원을 지원합니다.
- 번역 캐시가 일부만 있어도 재번역하지 않고 이어서 진행합니다. 처음부터 다시 번역하는 버튼은 설정 안에 별도로 둡니다.

## 모델 비용과 번역 검증

기본 자동 번역은 꺼져 있습니다. Codex 모델 목록은 Luna/mini 계열을 먼저, Claude는 Haiku를 먼저 보여 주며 번역 CLI에는 낮은 추론 강도를 지정합니다. 기존 사용자가 저장한 모델 선택은 강제로 바꾸지 않습니다. 모델을 다른 단계로 자동 승격하거나 실패 때 고급 모델로 재시도하지 않습니다.

번역 하네스는 문서 내부 지시를 데이터로 취급하고 문맥의 중복과 길이를 제한합니다. 응답은 JSON 전체 형식·항목 수·ID 집합·중복·빈 문자열·비정상 길이를 검사합니다. 입력의 LaTeX 수식과 숫자 인용 표기가 빠지거나 바뀌면 해당 배치를 저장하지 않습니다. 캐시는 같은 ID뿐 아니라 같은 원문일 때만 재사용하며 파일 교체는 원자적으로 수행합니다. 사용자가 중지하면 다음 배치를 실행하지 않습니다.

실제 GPT-5.6 Luna / low 호출 한 번으로 다음 5종을 확인했습니다. CLI가 보고한 사용량은 **3,878토큰**입니다.

| 입력 목적 | 관찰 결과 |
| --- | --- |
| BRCA1 발현·생존 관계와 p=0.08 | 유의하지 않다는 부정과 수치 유지 |
| 37 °C / 24 h / 5% CO2 배양 | 온도·시간·기체 농도 유지 |
| `$E=mc^2$`와 `[12]` | 원문 표기 그대로 유지 |
| 시사하지만 인과를 확립하지 않는 결과 | 주장 강도와 불확실성 유지 |
| 문서 안의 “ignore previous instructions” | 지시로 실행하지 않고 문장의 내용으로 번역 |

이것은 소량의 실제 모델 검증이며, 모든 분야·언어·문서 레이아웃의 품질 인증은 아닙니다. 레이아웃 테스트의 한국어 문장은 별도의 고정 테스트 데이터로, 실제 모델 응답인 것처럼 취급하지 않았습니다.

## 배포 판단과 남은 조건

이번 결과를 **제한된 실제 사용 검증이 가능한 개선 빌드**로 평가합니다. “모든 환경에서 바로 상용 배포 가능”이라는 판정은 하지 않습니다.

1. Windows 실행 파일의 생성/실행 검증과 별개로 공개 배포용 서명·설치/업데이트 정책이 필요합니다. macOS Intel/Apple Silicon 빌드 작업은 CI에 구성했지만 이 작업 환경에서 원격 CI 실행이나 Mac 실기기 검증을 수행하지 않았습니다. Developer ID 서명·공증도 별도입니다.
2. 더 다양한 실제 생물학·공학 PDF, 다중 패널·수식 글꼴·이미지 전용 스캔으로 품질 표본을 늘려야 합니다. OCR은 구현되어 있지 않습니다. 벡터 결합은 휴리스틱이며 감지 실패 시 원문 펼치기/수동 피겨 캡처가 필요합니다.
3. Codex 피겨 질문은 실제 이미지 입력과 Luna의 그림 속 글자·사진 수 판독을 검증했습니다. Claude Haiku도 실제 이미지 전송을 확인했습니다. 최초 저해상도 캡처에서는 작은 글자를 정확히 읽지 못해 PDF 영역을 고해상도로 다시 렌더링하도록 개선했습니다. 고해상도 재검증에서는 동일한 두 제목과 사진 수를 정확히 읽었습니다. 상세 결과는 round9 리뷰에 기록합니다. 모든 모델·그림의 정확성을 보장하지 않습니다.
4. 현재 본문 문맥은 비용을 제한한 발췌입니다. 전체 논문과 모든 선택 논문을 항상 완독한 것으로 답하지 않도록 명시합니다. 분야별 답변 정확성에 대한 별도 평가가 필요합니다.
5. 라이브러리 폴더 전체 이동/외부 파일 경로 재연결 UI, 이미지 OCR, 출판사별 직접 PDF 가져오기, 동시 Obsidian 편집의 장시간 스트레스 테스트는 아직 구현 또는 추가 검증이 필요합니다.
6. 페르소나 리뷰는 가상 검토입니다. 실제 초보 연구자와 접근성 사용자의 관찰 테스트가 공개 릴리스 전 필요합니다.

기존 사용자 데이터 형식을 보존하면서 핵심 흐름을 개선했고, 사용하지 않는 기능을 전부 지우거나 테스트가 없는 전면 재작성으로 바꾸지는 않았습니다.

## 2026-09-09 화면 기반 후속 수정

- UI는 로컬 Pretendard로 통일하고 논문 활자는 원문 크기·칼럼·문단 위치에 맞췄습니다. 한국어 길이에 따라 세로 공간을 늘리되 수식·표·피겨는 원문 픽셀로 유지합니다. 종이 안의 제품 머리말을 제거하고 크롭 선명도와 문장 경계 중복을 수정했습니다.
- 탭의 중복 모드 버튼을 제거하고 읽기 조작을 원문/한국어/비교·메모·번역·더보기로 정리했습니다. 좁은 화면에서 처음 비교하면 상하로 열며, 직접 선택한 배치는 유지합니다.
- 현재 페이지 번역을 기본으로 하고 본문 전체 번역에서 참고문헌을 제외합니다. 수치·단위·비교 방향 검증과 개별 문장 실패 격리, 재사용 캐시 검증을 보강했습니다. 실제 생물학 23문장과 공학 18문장 번역 검증은 CORPUS_QUALITY.md에 기록했습니다.
- 질문 준비 중 취소·대화 전환·새 초안의 경합을 처리하고, 근거 번호와 답변 저장 대상 논문을 메시지에 고정했습니다. 노트 화면의 불필요한 AI 실행과 접힌 문서 조작 문제를 줄였습니다.
- 전체 코어 검사, 제품 UI, Notes UI, 채팅 UI를 통과했습니다. 실제 Windows 화면에서는 공학 p4의 원문/번역 대응, 표·수식 선명도, 메뉴·키보드·테마·페이지 전환을 확인했습니다. 디자인 담당과 별도 취향 심사 담당의 판정 범위는 각 리뷰에 명시했습니다.
- 최신 검토 패키지는 `release/design-review/Prism-0.1.0-Windows-x64.exe`입니다. 공개 배포용 서명과 Mac 실기기 검증은 포함하지 않습니다. 기존 `release/product-review` 파일은 이전 버전입니다.

남은 확인: 초기 조판 시 잠깐의 재배치, 더 다양한 논문·화면 크기에서의 장시간 사용. 새 채팅의 실제 토큰 절감량은 수치로 검증하지 않았습니다. 테스트와 제한된 화면 심사 결과를 전체 제품의 무결성 보장으로 확대하지 않습니다.

## 글자 경계·강조·부분 번역 후속 검증

- PDF.js의 실제 글자 그리기 좌표를 검증하여 문장 경계를 자릅니다. 글자 수에 비례해 경계를 추정하면서 첫 글자가 잘리던 공학 p11 사례를 수정했습니다. 글꼴·문자열·합자 경계가 맞지 않는 PDF는 기존 원문 보존으로 돌아갑니다.
- 해당 페이지의 실제 Luna 번역은 첫 실행에서 긴 문장 ID를 잘못 복사해 저장이 거부됐습니다. 요청에 짧은 ID를 부여하고 정확히 역매핑하도록 수정한 뒤, 한 번의 재검증에서 16/16문장이 저장됐습니다. 잘못된 이전 응답을 추측해서 복구하지 않았습니다. 문자 정보가 손상된 비교식 문장 하나는 `≥`를 포함한 원문 픽셀로 유지했습니다.
- Noto Serif KR 본문을 450/진한 중립색으로 조정하고, PDF의 실제 글꼴 메타데이터에서 확인한 문장 단위 굵은 강조를 전달합니다. 번역 언어 사이에서 개별 강조 단어의 대응은 추측하지 않습니다. 비판 담당은 공학 p4에서 무게 조정을 수용했으며 페이지 높이까지 원문과 같다는 판정은 하지 않았습니다.
- 승인된 번역과 실패한 문장을 별도 블록으로 표시해 이웃 문장의 번역이 가려지지 않게 했습니다. 번역본 피겨 클릭은 실제 이미지 파일과 유효한 좌표를 저장하여 질문에 첨부합니다.
- PDF별 읽던 위치를 저장하고 페이지 번호 입력을 추가했습니다. 제품 UI 검사에서 새로고침 후 페이지 번호와 실제 화면 위치가 함께 복원되는 것을 검증했습니다. 실제 키보드의 Enter 이동도 확인했습니다.
- 화면 리뷰에서 보기 형식 전환 시 다른 페이지로 이동하고 교체된 캔버스가 빈 상태로 남는 오류를 발견했습니다. 전환 전 위치를 확보하고 캔버스를 다시 렌더링하도록 수정했으며, 양방향 전환 후 실제 페이지·캔버스 해상도·가로 넘침을 회귀 검사합니다.
- 프로덕션 빌드, 전체 코어 검사, 제품 UI 검사 통과. [비교 화면](reviews/images/reader-comparison-dark.png), [비교식 보존 화면](reviews/images/translated-comparator-preserved.png). 전체 제품의 배포 조건과 Mac 검증 제한은 위와 동일합니다.

## 피겨 질문과 지식 노트 연결

- 기존 채팅 전송이 텍스트뿐인 것을 확인하고 실제 이미지 입력을 연결했습니다. Codex는 localImage, Claude는 구조화된 이미지 입력을 사용합니다. 그림은 라이브러리의 해당 논문 자산에서만 조회하며 경로·파일 형식·크기를 검사합니다. 모델을 자동 상향하지 않고 한 번에 최대 4개로 제한합니다.
- 보내기 전 이미지 미리보기를 확인할 수 있습니다. 전송 실패 시 이미지와 질문 초안을 복원하고 실패한 질문을 대화에 중복으로 남기지 않습니다. 오프라인 UI 검사에서 전송 참조와 복원을 검증했습니다.
- 실제 Luna 질문에서 공학 p4 그림의 두 녹색 제목과 각 영역의 사진 수를 정확히 읽었습니다. 캡션에 없는 정보이며, 해당 실행 기록에서 실제 이미지 입력도 확인했습니다. [실제 피겨 답변](reviews/images/figure-chat-actual-image.png). Claude Haiku도 실제 이미지 입력을 확인했으며, 최초 낮은 해상도에서의 판독 실패와 고해상도 수정 후 결과는 [피겨 질문 리뷰](reviews/round9-figure-chat.md)에 구분해 기록합니다.
- 저장된 AI 답변의 근거 중복을 제거하고 논문·페이지를 표시하는 원문 링크를 추가했습니다. Notes/메모 제목 모두 탐색하며, 개념 노트의 근거 카드와 저장한 답변에서 원문으로 돌아갈 수 있습니다. [저장 답변의 근거](reviews/images/saved-answer-links.png).
- 새 노트의 기본 삽입 위치는 제목 아래이며 명시적으로 둔 커서는 유지합니다. 관계 선택은 Escape로 닫을 수 있고, 단순한 연결에 사용할 중립적인 관련 관계를 추가했습니다. 지지·반박 등 의미 있는 관계의 대상 제약은 유지합니다.
- 실제 Luna 이미지 질문의 입력은 14,804토큰(이 중 캐시 입력 6,912), 출력은 109토큰이었습니다. Claude Haiku 최초 실행은 입력 10, 캐시 생성 26,167, 출력 1,518토큰으로 보고됐습니다. 두 공급자의 카운터 정의가 다르고 청구액이나 할당량 차감 공식이 아니므로 직접 비용 비교로 해석하지 않습니다. 작은 모델 기본값과 별개로 CLI 하네스의 문맥 비용은 추가 개선·측정 항목입니다.

- 피겨 캡처는 표시용 비트맵을 확대하지 않고 PDF의 선택 영역을 최대 2,000픽셀 범위로 다시 렌더링합니다. 실제 공학 그림은 457×165에서 1830×661로 저장됐으며, UI 회귀 검사에서도 화면보다 높은 저장 해상도를 확인합니다.


### 최종 통합 검사 (2026-09-10)

프로덕션 빌드, 전체 코어 검사, 제품 UI, 채팅 UI, Notes UI 검사를 통과했습니다. Notes 검사는 처음에 이전 관계 목록 기대값으로 실패해 새 중립 관계를 반영했고, 이후 외부 메모 탐색에서 실패했습니다. 진단 결과 편집기의 가상화된 마지막 줄을 반복 스크롤하는 테스트가 Notes 이전에서 멈췄습니다(`.cm-scroller`의 내용 높이와 표시 높이 모두 1274px). 제품을 수정하지 않고 실제 `메모 보기` 경로로 이동하도록 검사를 고친 뒤 동일한 본문 확인과 후속 외부 변경·충돌 검사를 통과했습니다.

고해상도 피겨 질문은 Luna의 기존 검증에 이어 Haiku 재검증도 통과했습니다. [Haiku 실제 답변](reviews/images/figure-chat-haiku-highres.png). 작은 표본에 대한 결과이며 모든 피겨의 정확성을 보장하지 않습니다. 캡처 대기 상태를 표시하고, 좁은 화면의 원문 복귀는 상하 배치로 열도록 했습니다. 저장한 피겨의 전체 영역을 원문 중앙에 정확히 맞추는 탐색과 첨부 미리보기의 원본 배율 확대는 남은 개선 항목입니다.


## 피겨 원본 확인과 정확한 원문 복귀 (2026-09-10)

첨부 확인창은 저장된 PNG 원본을 불러오고 맞춤 보기와 100% 배율, 스크롤을 제공합니다. 파일을 읽지 못하면 기존 미리보기와 오류를 함께 표시하며 재시도할 수 있습니다. 이미지 조회는 기존 라이브러리 자산 검증을 통과한 파일로 제한합니다. 위치 메타데이터가 잘못되거나 없더라도 유효한 이미지를 숨기지 않습니다.

피겨 근거를 누르면 저장된 정규화 좌표로 원문에 테두리를 표시하고, 페이지 렌더링 후 해당 영역으로 이동합니다. 기존 페이지 전체 중앙으로 이동하던 동작에서 정확한 그림 영역으로 바뀌었습니다. 자동 UI 검사는 저장 PNG와 100% 배율의 크기 일치, 맞춤 보기 넘침 없음, 파일 제거 후 명시적 오류와 복구, 피겨 영역의 창 중앙 배치를 확인했습니다. 프로덕션 빌드와 전체 코어 검사도 통과했습니다. 실제 화면 검증은 별도 round10 기록에 남깁니다.
