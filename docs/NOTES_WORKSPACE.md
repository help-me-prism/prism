# Notes 작업 공간 (UI 2차)

2026-09-03, 브랜치 `feat/research-db`. 기능은 유지하고 화면 구조만 다시 잡은 기록이다.

## 왜 바꿨나

1차 UI는 기존 노트 창을 재활용해서 이런 문제가 있었다.

- **지식이 모달 안에 있었다.** 논문 노트는 왼쪽 목록에, 개념·주장·질문은 `연구 지식` 모달 안에 있었다. 같은 볼트의 같은 종류 파일인데 접근 경로가 달랐고, 그래프는 모달 안의 또 다른 모달이었다.
- **버튼이 너무 많고 숨어 있었다.** 툴바에 블록 삽입 11개 + 링크·지식·정리·템플릿·모드 3개 + 연결까지 한 줄에 있었다. 정작 "지금 뭘 해야 하는지"는 어디에도 없었다.
- **모드가 인지 부담이었다.** Live Edit / 읽기 / 분할을 사용자가 골라야 했다.
- **리더와의 관계가 안 보였다.** 노트 창에서 논문 리더로 가는 길이 없었다.

## 지금 구조

```text
┌ rail ┬ tree ─────────┬ tabs ─────────────────────┬ connections ──┐
│ 리더  │ vault-name    │ ● note-a  × │ ● note-b ×  │ 연결 그래프    │
│ 노트  │ 🔍 검색       ├───────────────────────────┤  (2홉 · 인용)  │
│ 정리³ │ + 새 노트     │ 논문                       │ 백링크         │
│ 검색  │ ▾ papers   12 │ 제목                       │ 인용 (자동)    │
│      │   note-a      │ ▾ 속성 7개                 │ 제안           │
│ 연결  │ ▾ concepts  8 │   유형·상태·읽기·범위·관계   │               │
│ 양식  │ ▾ claims    4 │                            │               │
│ 폴더  │ ▾ questions 2 │ 본문 (항상 Live Edit)      │               │
│      │ [정리 대기 3] │ PDF 근거 2                 │               │
└──────┴───────────────┴────────────────────────────┴───────────────┘
│ vault-name · 노드 26 · 이 노트 관계 3 · 백링크 5 · 정리 대기 3 · markdown │
```

- **왼쪽 레일**: 리더 / 노트 / 정리 대기열(배지) / 검색 · 연결 패널 토글 / 양식 / 라이브러리 폴더.
- **트리**: 볼트의 모든 노드를 폴더별로. 링크만 있고 아직 정리 안 한 개념은 기울임체로 흐리게 보인다. 검색창은 입력하면 제목 필터, Enter를 누르면 의미 검색.
- **탭**: 최근 연 노트 8개까지. 논문·개념·주장·질문이 같은 탭 줄에 선다.
- **문서**: 제목 + 접을 수 있는 속성 표 + 본문. 속성 표에는 관계가 행으로 들어가고, 검토 대기 AI 관계는 그 자리에서 승인·거절한다.
- **오른쪽**: 항상 떠 있는 연결 그래프(1~2홉, 인용 겹쳐보기), 백링크, 인용 레이어, 정리 대기열 바로가기.

## UX 규칙

1. **모드 없음.** 본문은 항상 Live Edit이다. 커서가 있는 블록만 Markdown 표기를 보여주고 나머지는 문서로 렌더링한다.
2. **버튼은 지금 할 수 있는 것만.** 문서 상단에는 `리더에서 열기`(논문만) · `링크` · `근거` 세 개와 `…` 메뉴뿐이다. 블록 삽입은 `/`와 본문 아래 `블록 삽입` 하나로 합쳤다.
3. **모달은 양식 관리 하나뿐.** 지식 노트, 그래프, 대기열, 근거 선택은 모두 창 안에서 처리한다.
4. **리더와 왕복이 보인다.** 레일 첫 버튼과 논문 노트의 `리더에서 열기`가 리더 창을 띄우고, 근거 카드를 누르면 PDF 원위치로 간다. 반대로 리더에서 문장을 우클릭해 담은 메모는 논문 노트에 바로 나타난다.
5. **색은 그대로.** 기존 크림·보라 팔레트를 유지하고, 노드 종류만 색 점으로 구분한다(논문 파랑 · 개념 초록 · 주장 황토 · 질문 보라 · 반박 빨강 점선).

## 유지된 계약

화면만 바뀌었고 저장 형식과 IPC는 그대로다. `shared/contracts/*.md`의 관계·캡처·정리·모델 제안·인용 계약은 유효하다. 새로 추가된 것은 두 가지다.

- `reader:open` — 노트 창에서 리더 창을 띄우고, arXiv ID를 주면 그 논문을 연다.
- `MarkdownEditorHandle.openInsertMenu()` — 커서 위치에 맞춰 `/` 블록 메뉴를 연다.

`KnowledgeManager.tsx`는 `NoteDocument.tsx`(문서), `ConnectionsPanel.tsx`(오른쪽), `NotesWindow.tsx`(셸)로 나뉘어 사라졌다. 공통 라벨과 관계 규칙은 `src/knowledgeModel.ts`에 모았다.

## 2026-09-05 손이 덜 가는 구조

노트를 안 쓰게 되는 이유는 하나였다. **쓸 게 너무 많았다.** 실제 Vault에는 관계 0개, 빈 개념 스텁 5개, 예전 양식의 빈 제목 8개만 남아 있었다. 그래서 기계가 쓸 수 있는 것은 전부 기계가 쓰도록 바꿨다.

### 논문 노트는 열면 이미 쓰여 있다

| 섹션 | 누가 | 근거 |
| --- | --- | --- |
| 한눈에 | 자동 | 초록 (모델 있으면 문제·방법·결과로 다시 씀) |
| 내가 헷갈린 것 | 자동 | 이 논문 맥락의 채팅에서 **사용자 질문만**. 반복하면 "2번 물어봄" |
| 내가 주목한 것 | 자동 | 채팅에서 태그한 앵커를 참조 횟수 순으로 |
| 내 생각 | 사용자 | 자동 정리가 절대 건드리지 않음 |
| 메모 | 사용자·리더 | 우클릭 캡처가 쌓임 |

자동 구간은 `<!-- prism:auto ... -->` 마커 안에만 쓴다. 노트를 열면 비용 없는 결정적 갱신이 한 번 돌고, 모델 호출은 `자동 정리 갱신`을 눌렀을 때만 한다. **뽑을 게 없으면 이미 쓴 내용을 지우지 않는다** — 채팅을 잠깐 못 읽어도 노트가 비지 않는다. 계약은 `shared/contracts/paper-digest.md`.

### 링크가 곧 관계

`[[링크]]`를 쓰면 그 자체로 그래프 엣지가 된다(`origin: 'link'`). 관계 유형을 고를 필요가 없고, 나중에 `관계 지정`으로 `정의함`·`지지함` 같은 유형을 붙이면 링크 엣지는 그 자리를 내준다. 링크를 지우면 엣지도 사라지지만, 직접 승인한 유형 관계는 남는다. 링크 엣지는 Markdown에 관계 블록을 만들지 않는다 — 본문의 링크가 이미 사람이 읽는 형태이기 때문이다.

문서의 링크는 클릭하면 그 노트로 이동한다(Alt+클릭은 커서 놓기).

### 트리에서 바로

- 논문·개념·주장·질문 네 폴더는 비어 있어도 항상 보인다. 무엇을 만들 수 있는지가 먼저 보여야 한다.
- 폴더의 `+`로 그 유형의 노트를 바로 만든다.
- 행의 휴지통으로 삭제하고, 알림의 `실행 취소`로 되돌린다. 삭제는 `.prism/trash/knowledge/`로 옮기는 것이라 파일은 남는다.
- `…` 메뉴의 `빈 양식 섹션 정리`는 내용이 하나도 없는 제목만 지운다.

### 쓸 자리를 보여준다

자동 구간이 채워지고 나면 정작 **자기 문장을 어디에 쓰는지**가 안 보인다. 그래서 둘을 더했다.

- 본문 아래 `내 생각 쓰기`를 누르면 `## 내 생각` 바로 아래 빈 줄로 커서가 간다. 논문 노트에만 나온다.
- 비어 있는 `내 생각`·`메모` 섹션에는 회색 안내 문구가 뜬다. **파일에는 아무것도 안 쓴다** — 에디터 장식이라 Obsidian에서 열면 그대로 빈 섹션이다.

PDF 근거 카드는 통째로 렌더된 블록이 됐다. 커서가 들어가지 않으니 옆을 클릭하고 타이핑해도 카드가 깨지지 않고, 카드를 누르면 PDF 원위치로 간다. 카드가 깨지면 그 아래 메모가 승격 대상으로 잡히지 않아 `정리 대기열`이 조용히 비어버리던 문제가 있었다.

### 이번에 고친 버그

- `[[Concepts]]`처럼 **폴더 이름만 적은 링크가 개념 노트로** 만들어지던 문제. 이제 볼트 폴더 이름은 건너뛴다.
- `[[Concepts/generative]]`에서 "개념으로 만들기"를 누르면 `Concepts generative`라는 **경로가 이름에 박힌 노트**가 생기던 문제. 마지막 조각만 이름으로 쓰고, 같은 이름이 있으면 그것을 쓴다.

## 검증

`npm run test:notes-ui`가 새 화면 기준으로 셸·문서·속성·관계·근거·대기열·충돌·검색을 검증한다. `npm run test:capture`에 `test-paper-digest.mjs`(자동 정리)와 `test-curation.mjs`의 링크 관계·삭제 복구가 들어 있다. 캡처는 `tmp/ui/notes-shell.png`, `notes-graph-panel.png`, `notes-curation-queue.png`, `notes-scope-warning.png`, `notes-conflict.png`.

`node scripts/e2e-research-session.mjs <라이브러리> [포트]`는 실제 논문 3개로 **한 세션 전체**를 돌린다. 원본 라이브러리를 복사해 노트 0개·채팅 0건인 볼트를 만들고, 리더에서 문장을 우클릭해 담고, 채팅을 남기고, Notes를 열어 자동 정리를 확인하고, 내 문장을 한 줄 쓰고, 대기열에서 메모를 주장으로 승격시킨 뒤 볼트에 남은 파일과 관계를 검사한다. 원본 볼트에는 절대 쓰지 않는다. 캡처는 `tmp/ui/e2e-*.png`.

PDF 문장 오버레이는 논문을 열고 나서 전체 페이지 구조를 분석한 뒤에야 뜬다(진행률은 `논문 구조와 참조 위치를 분석하고 있어요` 막대에 나온다). 큰 논문에서는 수십 초가 걸릴 수 있어서, 세션 테스트는 90초를 기다린 뒤에도 오버레이가 없으면 캡처 패널과 같은 IPC로 우회하고 그 사실을 finding으로 남긴다 — 리더가 느린 것 때문에 노트 쪽 결함이 가려지지 않게.

## 2026-09-05 노드마다 무엇이 자동인가

"열면 이미 쓰여 있다"를 논문 노트에만 적용했더니, 개념·주장·질문은 여전히 빈 양식이었다. 이제 **어떤 노트가 어떤 구간을 스스로 쓰는지**를 `electron/paperDigest.ts`의 `noteAutomation` 표 하나가 정한다. 표에 없는 것은 전부 사용자 것이고 자동 정리가 건드리지 않는다.

| 노드 | 기계가 씀 (열 때마다, 공짜) | 모델이 씀 (`자동 정리 갱신`을 눌렀을 때만) |
| --- | --- | --- |
| 논문 | 내가 헷갈린 것, 내가 주목한 것 | 한눈에 (초록에서 기계가 먼저 쓰고, 모델이 있으면 다시 씀) |
| 개념 | 어디서 나왔나, 대화에서 물어본 것 | 정의 |
| 주장 | 어디서 나왔나, 지지 근거, 반박, 대화에서 물어본 것 | 무엇에 달려 있나 |
| 질문 | 어디서 나왔나, 지금까지 나온 답, 대화에서 물어본 것 | — |

- **모델 구간은 볼트에 있는 재료로만 쓴다.** 노트의 인용문·정의 비교 표 행·링크한 문장, 그리고 링크한 논문 초록에서 그 노트를 언급하는 문장만 넘긴다. 재료가 얇으면 모델은 빈 배열을 돌려주도록 되어 있고, 그러면 **이미 쓰인 내용을 지우지 않는다**.
- **모델이 없으면 모델 구간은 손대지 않는다.** 오늘 CLI가 없다는 것이 어제 쓴 정의가 틀렸다는 뜻은 아니다.

### 대화가 노트를 갱신한다

채팅이 잦아들면(마지막 저장 후 4초) 그 대화가 다룬 노트들이 스스로 따라잡는다 — 대화 맥락에 있던 논문, 그리고 사용자가 이름을 부른 개념·주장·질문. 제목은 머리글자로도 부른다(`Optimal Transport` ↔ `OT`). 모델을 부르지 않는 공짜 갱신이라 배경에서 조용히 돈다. `electron/main.ts`의 `routeChatIntoNotes`.

### 질문에 답을 연결한다

`answers` 관계는 답하는 노트에 저장되기 때문에, 정작 질문 노트에서는 만들 길이 없었다. 질문 노트 속성표의 `답 연결`이 답하는 노트를 고르게 하고 관계는 그쪽에 쓴다.
