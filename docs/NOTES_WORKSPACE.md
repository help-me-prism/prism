# Notes 작업 공간 (UI 2차)

2026-09-03, 브랜치 `feat/research-db`. 기능은 유지하고 화면 구조만 다시 잡은 기록이다.

## 왜 바꿨나

1차 UI는 기존 노트 창을 재활용해서 이런 문제가 있었다.

- **지식이 모달 안에 있었다.** 논문 노트는 왼쪽 목록에, 개념·주장·질문은 `연구 지식` 모달 안에 있었다. 같은 볼트의 같은 종류 파일인데 접근 경로가 달랐고, 그래프는 모달 안의 또 다른 모달이었다.
- **버튼이 너무 많고 숨어 있었다.** 툴바에 블록 삽입 11개 + 링크·지식·정리·템플릿·모드 3개 + 연결까지 한 줄에 있었다. 정작 "지금 뭘 해야 하는지"는 어디에도 없었다.
- **모드가 인지 부담이었다.** Live Edit / 읽기 / 분할을 사용자가 골라야 했다.
- **리더와의 관계가 안 보였다.** 노트 창에서 논문 리더로 가는 길이 없었다.

## 지금 구조

```text
┌ rail ┬ tree ─────────┬ tabs ─────────────────────┬ connections ──┐
│ 리더  │ vault-name    │ ● note-a  × │ ● note-b ×  │ 연결 그래프    │
│ 노트  │ 🔍 검색       ├───────────────────────────┤  (2홉 · 인용)  │
│ 정리³ │ + 새 노트     │ 논문                       │ 백링크         │
│ 검색  │ ▾ papers   12 │ 제목                       │ 인용 (자동)    │
│      │   note-a      │ ▾ 속성 7개                 │ 제안           │
│ 연결  │ ▾ concepts  8 │   유형·상태·읽기·범위·관계   │               │
│ 양식  │ ▾ claims    4 │                            │               │
│ 폴더  │ ▾ questions 2 │ 본문 (항상 Live Edit)      │               │
│      │ [정리 대기 3] │ PDF 근거 2                 │               │
└──────┴───────────────┴────────────────────────────┴───────────────┘
│ vault-name · 노드 26 · 이 노트 관계 3 · 백링크 5 · 정리 대기 3 · markdown │
```

- **왼쪽 레일**: 리더 / 노트 / 정리 대기열(배지) / 검색 · 연결 패널 토글 / 양식 / 라이브러리 폴더.
- **트리**: 볼트의 모든 노드를 폴더별로. 링크만 있고 아직 정리 안 한 개념은 기울임체로 흐리게 보인다. 검색창은 입력하면 제목 필터, Enter를 누르면 의미 검색.
- **탭**: 최근 연 노트 8개까지. 논문·개념·주장·질문이 같은 탭 줄에 선다.
- **문서**: 제목 + 접을 수 있는 속성 표 + 본문. 속성 표에는 관계가 행으로 들어가고, 검토 대기 AI 관계는 그 자리에서 승인·거절한다.
- **오른쪽**: 항상 떠 있는 연결 그래프(1~2홉, 인용 겹쳐보기), 백링크, 인용 레이어, 정리 대기열 바로가기.

## UX 규칙

1. **모드 없음.** 본문은 항상 Live Edit이다. 커서가 있는 블록만 Markdown 표기를 보여주고 나머지는 문서로 렌더링한다.
2. **버튼은 지금 할 수 있는 것만.** 문서 상단에는 `리더에서 열기`(논문만) · `링크` · `근거` 세 개와 `…` 메뉴뿐이다. 블록 삽입은 `/`와 본문 아래 `블록 삽입` 하나로 합쳤다.
3. **모달은 양식 관리 하나뿐.** 지식 노트, 그래프, 대기열, 근거 선택은 모두 창 안에서 처리한다.
4. **리더와 왕복이 보인다.** 레일 첫 버튼과 논문 노트의 `리더에서 열기`가 리더 창을 띄우고, 근거 카드를 누르면 PDF 원위치로 간다. 반대로 리더에서 문장을 우클릭해 담은 메모는 논문 노트에 바로 나타난다.
5. **색은 그대로.** 기존 크림·보라 팔레트를 유지하고, 노드 종류만 색 점으로 구분한다(논문 파랑 · 개념 초록 · 주장 황토 · 질문 보라 · 반박 빨강 점선).

## 유지된 계약

화면만 바뀌었고 저장 형식과 IPC는 그대로다. `shared/contracts/*.md`의 관계·캡처·정리·모델 제안·인용 계약은 유효하다. 새로 추가된 것은 두 가지다.

- `reader:open` — 노트 창에서 리더 창을 띄우고, arXiv ID를 주면 그 논문을 연다.
- `MarkdownEditorHandle.openInsertMenu()` — 커서 위치에 맞춰 `/` 블록 메뉴를 연다.

`KnowledgeManager.tsx`는 `NoteDocument.tsx`(문서), `ConnectionsPanel.tsx`(오른쪽), `NotesWindow.tsx`(셸)로 나뉘어 사라졌다. 공통 라벨과 관계 규칙은 `src/knowledgeModel.ts`에 모았다.
