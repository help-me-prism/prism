# Prism 제품 완성도 리뷰

마지막 갱신: 2026-09-02  
검토 브랜치: `kys_enhanced`

이 문서는 Prism을 실제 사용자처럼 실행하고 관찰한 문제, 수정 결정, 검증 결과를 반복해서 기록한다. 단순 아이디어 목록이 아니라 각 항목을 `발견 → 수정 → 재검증` 상태로 관리한다.

## 평가 원칙

- 첫 실행부터 논문 검색, 저장, 읽기, 번역, 태그, 질문, 노트 작성까지 하나의 사용자 여정으로 본다.
- 기능이 존재하는지만 확인하지 않고 현재 상태, 다음 행동, 실패 원인, 복구 방법이 화면에서 이해되는지 확인한다.
- 실제 Electron 창을 1480×920과 최소 창 크기 1040×680에서 캡처해 가독성, 잘림, 포커스, 빈 상태를 확인한다.
- Windows에서 실행 검증하고, 경로·단축키·창 동작·셸 호출은 macOS에서도 성립하도록 구현한다.
- 각 반복이 끝날 때 `npm run build`와 Electron UI smoke 검증을 실행한다.

## 2차 관찰 — 실제 논문 저장과 리더 진입

테스트 논문: Attention Is All You Need (`1706.03762`, 15페이지)

| 우선순위 | 영역 | 관찰 | 조치 | 상태 |
| --- | --- | --- | --- | --- |
| P0 | 리더 초기 성능 | 저장 직후 리더가 사용 가능해지기까지 약 24초 동안 일반적인 “PDF를 불러오는 중” 화면만 보였다. | 소스 피겨 preview 준비를 PDF 로드와 병렬화하고, 화면에서 1,000px 이내인 페이지만 canvas·operator 분석을 수행하도록 lazy rendering을 적용했다. | 완료 |
| P0 | 진행 피드백 | PDF 다운로드, 문장 분석, 피겨 준비를 구분할 수 없었다. | PDF가 열리면 먼저 첫 페이지를 표시하고 전체 문장/앵커 분석은 페이지 진행률 bar로 알리도록 분리했다. | 완료 |
| P1 | 리더 가독성 | 번역 설정과 문서 pane header가 8px라 읽기 어려웠다. | 번역 컨트롤과 문서 상태를 10px 이상으로 높이고 대비를 강화했다. | 완료 |
| P1 | 긴 문서 메모리 | 모든 페이지의 원문/번역 canvas를 동시에 렌더링해 페이지 수에 비례해 메모리와 초기 연산이 증가했다. | 보이는 영역 인접 페이지부터 한 번만 활성화하는 lazy rendering으로 전환했다. | 완료 |
| P1 | 노트 저장 안정성 | 논문을 빠르게 전환하거나 Notes 창을 바로 닫으면 500ms debounce 중인 변경이 저장되지 않을 가능성이 있다. | 논문/라이브러리 전환, textarea blur, 창 unload에서 dirty note를 flush하고 debounce를 300ms로 줄였다. | 완료 |
| P1 | 번역 제어 | 번역이 시작되면 UI 버튼이 비활성화되어 메인 프로세스에 이미 존재하는 취소 기능을 사용할 수 없었다. | 진행 중 버튼을 `번역 중지`로 바꾸고 완료된 batch cache를 유지한 채 CLI 작업을 종료한다. | 완료 |

## 후속 집중 검토

첫 실행 개선 후 실제 논문을 테스트 라이브러리에 저장해 다음을 별도 반복한다.

1. PDF 로딩 중·실패·대용량 문서 상태와 페이지 이동
2. 원문/한국어/병기 모드의 글자 겹침, 2단 컬럼, 확대 및 스크롤 동기화
3. 문장·수식·피겨 태그의 발견 가능성, 키보드 조작, 채팅 이동
4. 번역 시작·취소·실패·재시도·앱 재시작 후 복구
5. Notes 창의 저장 상태, 창 닫기 직전 저장, 상대 경로 표시
6. 최소 창 크기와 Windows/macOS 단축키 차이
