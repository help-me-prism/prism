# Editor reference authoring contract

Use case: a user can create knowledge and evidence references at the current visual-editor cursor without typing Markdown syntax, and can inspect a knowledge link before opening it.

## Knowledge options

Each editor knowledge option is JSON-serializable and contains:

```ts
type WikiLinkOption = {
  id: string
  label: string
  target: string
  description: string
  preview: string
  evidenceCount: number
}
```

- Typing `[[` filters the options and inserts portable `[[Vault/relative/path|label]]` Markdown.
- Hovering a rendered link shows node type, a bounded plain-text preview, and the number of embedded PDF evidence cards.
- If a non-empty search has no exact title match, the picker offers explicit `Concept로 만들기` and `Claim으로 만들기` actions. Creation never happens on typing alone.
- The toolbar link picker exposes `관계 없음` plus the bounded relationship enum. Choosing a relationship creates an approved user relation and a human-readable Markdown relationship block. The ordinary wiki link is also retained.

## Evidence options

Each evidence option contains a stable anchor identity, display metadata, search text, and the complete portable evidence-card Markdown generated by Notes.

- Typing `@` after whitespace or at line start opens evidence autocomplete for the Vault's current sentence, equation, table, figure, and page anchors.
- Choosing an option replaces only the active `@query` token with one evidence-card block at the cursor.
- Existing identical evidence in the note is not offered as a duplicate.
- Escape closes the active suggestion menu; arrow keys and Enter/Tab select without changing the surrounding text.

## Safety

- The editor owns cursor and text insertion; no DOM, React state, or CodeMirror object crosses IPC.
- Inline creation uses the existing validated `knowledge:create` boundary.
- Link-plus-relation creation first conflict-safely saves the inserted wiki link, then creates the relation with the returned revision. If either revision check fails, no disk content is overwritten.
- Chat code and `chat:*` IPC remain unchanged.
